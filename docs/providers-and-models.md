# Подключение провайдера и моделей (для нового пользователя)

Краткая инструкция: как в Harbor Agents подключить API-провайдера, подтянуть из него список моделей и при необходимости отключить проверку TLS-сертификата (корпоративный прокси с самоподписанным сертификатом). Шаги одинаковы для VS Code и WebStorm — панель настроек общая.

Названия пунктов даны как «русские (English)» — панель переключается в Settings → Language.

## Что понадобится

- Любой OpenAI-совместимый API: **Base URL** (например, `https://api.openai.com/v1`) и **API key**. Подходит OpenAI, Z.AI, OpenRouter, LiteLLM, корпоративный шлюз и т.п.
- Либо endpoint, говорящий только на Anthropic Messages API — тогда при добавлении провайдера выберите Protocol `Anthropic`.

## 1. Откройте настройки

1. Откройте панель: Command Palette → **Harbor Agents: Open**.
2. Нажмите **Settings** (шестерёнка) в панели.
3. Первый раздел — **«Модели и провайдеры» (Models & providers)**.

## 2. Добавьте провайдера

1. Нажмите **«+ Провайдер» (+ Provider)**.
2. Заполните поля:

| Поле | Что вводить |
|------|-------------|
| **ID** | Короткий идентификатор: `zai`, `openai`, `kimi`… |
| **Имя (Name)** | Отображаемое имя: «Z.AI», «OpenAI»… |
| **Base URL** | Корень API, обычно заканчивается на `/v1`: `https://api.openai.com/v1`, `https://api.z.ai/api/paas/v4`, адрес корпоративного LiteLLM |
| **URL проверки статуса (Status URL)** | Необязательно. Пусто = `Base URL + /models` |
| **API Key** | Ключ провайдера (`sk-…`) |
| **Protocol** | `OpenAI-compatible (Chat Completions)` — по умолчанию; `Anthropic (Messages API)` — только для прокси, которые принимают Messages API |
| **Prompt cache** | Выключено по умолчанию. Включайте только для апстримов, принимающих `cache_control` (LiteLLM / OpenRouter / Anthropic-совместимые); строгий OpenAI ответит 400 |

3. Нажмите **Done**.

Карточка провайдера появится в списке с индикатором состояния: Harbor сразу проверяет доступность (по Status URL или `Base URL + /models`). Зелёная точка — URL и ключ работают.

## 3. Подтяните модели из API

1. На карточке провайдера нажмите кнопку со стрелкой-облаком (⭳) — **«Подтянуть модели» (Fetch models)**.
2. Harbor выполнит `GET {Base URL}/models` с вашим ключом и покажет список моделей.
3. Отметьте нужные (есть поле фильтра; **«Выбрать новые» (Select new)** отмечает только ещё не добавленные) и нажмите **«Добавить выбранные» (Add selected)**.

Модели появятся в списке, сгруппированные по провайдеру.

Альтернативные способы добавить модели:

- **«+ Модель» → вкладка From API** — то же самое, но провайдера можно создать прямо в этом окне;
- **вкладка Manual** — вписать `id` модели руками (если endpoint не отдаёт `/models`);
- **вкладка JSON** — вставить список моделей разом.

## 4. Выберите модель в чате

Откройте выпадающий список моделей внизу панели, выберите модель и отправьте любое сообщение — это end-to-end проверка связки «провайдер + ключ + модель».

## 5. Отключение проверки TLS-сертификата

Когда это нужно: провайдер сидит за корпоративным прокси/шлюзом с самоподписанным сертификатом, и индикатор провайдера красный с ошибкой вида `unable to verify the first certificate` / `self-signed certificate in certificate chain`.

### 5.1. Автодоверие внутреннему CA (рекомендуется, включено по умолчанию)

Прежде чем отключать проверку, попробуйте автоматический сценарий (trust-on-first-use): при первой ошибке строгой проверки Harbor сам снимает цепочку сертификатов с эндпоинта и показывает модальный вопрос — «Обнаружен внутренний сертификат … Доверять этому CA только для <host>?». После «Да» цепочка сохраняется в `~/.harbor/certs/pinned/<host>.pem`, и все дальнейшие запросы к этому хосту проходят **строгую** проверку по закреплённой цепочке — как `known_hosts` у SSH.

- Настройка: `agentPanel.tls.autoTrustInternalCa` (вкл. по умолчанию). Выключите, если автодоверие не нужно.
- Не предлагается доверять сертификатам с несовпадающим hostname или истёкшим сроком — это признаки MITM.
- Если цепочка для хоста изменится, вопрос покажется снова с пометкой об обновлении доверия.
- Пин общий для всех оболочек: принятый в VS Code хост автоматически доверен в WebStorm-сайдкаре и Figma-плагине (общий `~/.harbor/certs/pinned/`). В headless-оболочках без UI в лог пишется подсказка — принять можно в VS Code или положить pem-файл вручную.
- Ручной путь без диалога: сохранить цепочку (`openssl s_client -showcerts -connect host:443 </dev/null | awk '/BEGIN CERT/,/END CERT/{print}' > ~/.harbor/certs/pinned/<host>.pem`).
- Альтернатива уровня процесса: запустить IDE с `NODE_EXTRA_CA_CERTS=<путь к pem>`.

### 5.2. Отключение проверки (когда автодоверие не подходит)

1. В Settings откройте раздел **«Доп. настройки» (Advanced)**.
2. Снимите галочку **«Проверять TLS-сертификат» (Validate TLS certificate)**.

Эквивалент в `settings.json`:

```json
"agentPanel.rejectUnauthorized": false
```

- По умолчанию проверка **включена** (`true`, строгая проверка по системному хранилищу сертификатов).
- Применяется сразу, без перезагрузки окна: проверка статуса провайдера, «Подтянуть модели» и новые ходы чата уходят уже с новой политикой.
- Действие ограничено запросами самого Harbor (провайдеры, `/models`, чат); переменная окружения `NODE_TLS_REJECT_UNAUTHORIZED` не изменяется.
- ⚠️ Небезопасно: отключённая проверка открывает путь для MITM (и деградирует стриминг чата — ответы буферизуются). Включайте только для доверенных корпоративных шлюзов и верните галочку, когда появится CA bundle; предпочтителен сценарий 5.1.

## Если что-то не работает

| Симптом | Что проверить |
|---------|---------------|
| Индикатор красный, 401 / 403 | Неверный API key |
| Ошибка `self-signed certificate` / `unable to verify` | Шаг 5.1 — доверить внутренний CA (вопрос-модалка); шаг 5.2 — отключение проверки как последний вариант |
| «Подтянуть модели» вернул пустой список | Base URL без `/v1` (или другой правильный суффикс провайдера); либо endpoint не отдаёт `/models` — добавьте модель через Manual |
| Модель выбрана, но чат падает | `id` модели существует у провайдера; Protocol соответствует API (`Anthropic` для Messages API) |

## Альтернатива: настроить через settings.json

Те же данные можно вписать прямо в настройки VS Code (Settings → Extensions → Harbor Agents или JSON):

```json
{
  "agentPanel.providers": [
    {
      "id": "openai",
      "name": "OpenAI",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "sk-..."
    }
  ],
  "agentPanel.models": [{ "id": "gpt-4o-mini", "label": "GPT-4o mini" }],
  "agentPanel.defaultModel": "gpt-4o-mini"
}
```

Полный пример — [`docs/harbor-settings.example.json`](harbor-settings.example.json). Ключи и настройки хранятся только в вашем VS Code storage / settings; см. «Приватность» в README.
