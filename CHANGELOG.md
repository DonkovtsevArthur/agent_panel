# Changelog

История изменений **Harbor Agents** (Гавань агентов). Вкладка **Changelog** на странице расширения в Marketplace.

## [2.9.83] — 2026-10-15

- **Метки ходов в VS Code — по центру:** в VS Code все метки мини-карты слипались в одну точку у верхнего края. Причина — политика безопасности webview (CSP) молча отбрасывала их позицию, заданную атрибутом `style`. Теперь позиция ставится из скрипта, и стопка встаёт по центру, как в WebStorm. Работает в VS Code и WebStorm

## [2.9.82] — 2026-10-15

- **Метки ходов не слипаются в одну точку наверху:** если мини-карта считалась, пока вкладка с чатом была скрыта или ещё не разложена (VS Code держит фоновые вкладки нулевой высоты), все метки рисовались одной точкой у верхнего края. Теперь при такой высоте карта не рисуется и пересчитывается через мгновение, а высота берётся из реального размера ленты. Работает в VS Code и WebStorm

## [2.9.81] — 2026-10-15

- **Метки ходов остаются по центру:** если панель разворачивали или меняли её размер, стопка меток могла остаться у верхнего края. Теперь она пересчитывается при изменении размера окна, показе панели и наведении на метки. Работает в VS Code и WebStorm

## [2.9.80] — 2026-10-15

- **Закреплённый вопрос после «Собрать»:** при прокрутке ответа сверху показывался служебный текст «[[harbor:implement_plan]] Реализуй следующий план…». Теперь там «Собрать план · цель плана»; то же в подсказках мини-карты ходов. Работает в VS Code и WebStorm
- **Мини-карта ходов — компактная стопка:** метки справа раньше разбегались по всей высоте и наезжали на ползунок. Теперь это ровная стопка с шагом 8px по центру высоты чата, вплотную слева от полосы прокрутки (10px); в длинных чатах шаг сжимается. При наведении на метку слева появляется подсказка «номер · вопрос» — своя, поэтому в VS Code и WebStorm она выглядит одинаково. Работает в VS Code и WebStorm

## [2.9.79] — 2026-10-15

- **План над полем ввода больше не дёргается:** раскрытый список шагов перестраивался при каждом изменении чата — тике таймера, потоке текста — и прокрутка прыгала наверх. Теперь он перерисовывается только при изменении самих шагов, сохраняет прокрутку и подкручивает к текущему шагу. Работает в VS Code и WebStorm
- **«Собрать план» — работает «Показать план / Свернуть»:** у сообщения «Собрать план» кнопка раньше ничего не меняла — план был скрыт за коротким чипом. Теперь «Показать план · N строк» раскрывает его под чипом, «Свернуть» прячет, а клик по тексту плана не запускает редактирование сообщения. Работает в VS Code и WebStorm

## [2.9.78] — 2026-10-15

- **Карточка задач идёт вровень с работой:** когда агент пишет «Шаг N — …», карточка сразу отмечает предыдущие пункты выполненными, а N — текущим, не дожидаясь `update_todo`. Агента попросили так подписывать переходы между шагами. Карточка двигается только вперёд. Работает в VS Code и WebStorm
- **Напоминание обновить карточку больше не кончается:** раньше на весь ход было максимум два напоминания, и на длинной сборке карточка застревала на середине («План не обновлялся · с тех пор 12 правок»). Теперь лимит сбрасывается после каждого обновления карточки. Работает в VS Code и WebStorm

## [2.9.77] — 2026-10-15

- **Карточка плана — новый вид:** вместо сплошного текста карточка разбита на разделы. «Контекст» свёрнут в строку «N мест в коде», шаги идут лентой с жирными заголовками, а «Затронутые файлы» сгруппированы по папкам. Длинные пути показаны короткими чипами вида `model.ts:198` — клик открывает файл сразу на нужной строке. Цель показана один раз, в шапке. Работает в VS Code и WebStorm
- **Карточка плана — действия:** если раздела «Проверка» нет, на его месте блок с кнопкой «Дополнить» — агент допишет недостающие разделы. В подвале карточки кнопки «Изменить» (открывает План.md, не затирая ваши правки) и «Собрать». Работает в VS Code и WebStorm
- **Режим Plan — заголовки шагов:** модель начинает каждый шаг с короткого заголовка жирным, чтобы шаги читались с одного взгляда. Работает в VS Code и WebStorm

## [2.9.76] — 2026-10-15

- **Карточка плана — нагляднее:** последний план раскрыт сразу; в шапке видны цель и счётчики «N шагов · M файлов». Шаги показаны пронумерованной лентой, а «Затронутые файлы» — строками со значком создать / изменить / удалить. На карточке появились кнопки «Собрать» и «Скопировать план». Старые планы сворачиваются с пометкой «Выполнен» или «Заменён». Работает в VS Code и WebStorm
- **Карточка плана — предупреждения:** если в плане нет обязательных разделов (Цель, Шаги, Затронутые файлы, Проверка), карточка пишет «Не хватает: …». Обрезанный план помечается «План обрезан» и получает кнопку «Продолжить план». Если План.md поправили в редакторе, на карточке появляется «Изменён в редакторе» — «Собрать» возьмёт версию из редактора. Работает в VS Code и WebStorm
- **Режим Plan — напоминание о чек-листе:** в Plan напоминание `update_todo` просит чек-лист исследования, а не шаги реализации. Работает в VS Code и WebStorm

## [2.9.75] — 2026-10-15

- **Режим Plan — полнее и без «Act mode»:** план теперь строится по шаблону — Цель, Контекст с `путь:строка`, Шаги с файлами, Затронутые файлы, Проверка, Риски, Вне рамок — и пишется самодостаточно, потому что «Собрать» передаёт агенту только текст плана. Если подход неясен, модель сначала задаёт вопрос, а не выдаёт план. Модель больше не просит «переключиться в Act mode» и указывает на кнопку «Собрать». Карточка задач в Plan отслеживает только ход исследования и не «съедает» сам план. Работает в VS Code и WebStorm

## [2.9.74] — 2026-10-15

- **«Закоммитить» — все файлы чата разом:** раньше кнопка над полем ввода брала только файлы последнего хода агента, и изменения чата уходили несколькими коммитами по одному ходу. Теперь она коммитит одним коммитом все незакоммиченные файлы, которые агент менял в этом чате за все ходы; цифры +/− считаются по ним же. Ручные правки вне чата по-прежнему не попадают в коммит. Работает в VS Code и WebStorm

## [2.9.73] — 2026-10-15

- **«Закоммитить» — сообщение отклонил хук репозитория:** модель могла написать слишком длинный заголовок коммита, и `commit-msg` хук (например, «первая строка — не длиннее 100 символов») отклонял коммит. Теперь в запросе к модели заголовок ограничен 72 символами, а если хук всё же отклонил сообщение, Harbor один раз генерирует новое с учётом вывода хука и повторяет коммит. Работает в VS Code и WebStorm

## [2.9.72] — 2026-10-15

- **«Закоммитить» — ошибка `index.lock: File exists`:** если в этот момент VS Code сам обновлял состояние Git, `git add` / `git commit` из панели падали с ошибкой о занятом `index.lock`. Теперь Harbor несколько раз повторяет команду с короткой паузой и показывает ошибку, только если блокировка не снялась. Работает в VS Code и WebStorm

## [2.9.71] — 2026-10-15

- **«Закоммитить» больше не зависает:** если модель для сообщений коммита не выбрана или недоступна, Harbor показывал уведомление «Выбрать» и считал чат занятым, пока это уведомление не закроют, — повторные нажатия на «Закоммитить» молча игнорировались. Теперь чат освобождается сразу, а уведомление остаётся подсказкой. Работает в VS Code и WebStorm

## [2.9.70] — 2026-10-15

- **Ответ на языке интерфейса:** в конце длинного хода некоторые модели (например, DeepSeek flash) переходили на китайский. Теперь в каждом ходе модели напоминается, на каком языке отвечать, а если итоговый ответ всё же получился в основном на китайском (код и пути не считаются), Harbor один раз просит модель переписать его на языке интерфейса — в ленте виден шаг «Модель ответила не на языке интерфейса…». Если пользователь сам пишет по-китайски, ответ не переписывается. Работает в VS Code и WebStorm

## [2.9.69] — 2026-10-15

- **Панель — лишняя горизонтальная полоса прокрутки внизу:** мини-карта ходов у правого края выступала за панель на пару пикселей, и VS Code показывал горизонтальный скролл под полем ввода. Теперь мини-карта не расширяет панель. Работает в VS Code и WebStorm

## [2.9.68] — 2026-10-15

- **План не отстаёт от работы:** если агент долго правит файлы и запускает команды, но не обновляет карточку плана (8 вызовов инструментов или 3 правки после последнего обновления), ему приходит напоминание синхронизировать план и честно отметить пропущенные или переставленные шаги (не больше 2 раз за ход). В полоске плана над полем ввода появляется пометка «План не обновлялся · с тех пор N правок». Работает в VS Code и WebStorm

## [2.9.67] — 2026-10-14

- **Лента — разделители «Сегодня / Вчера» в старых чатах:** раньше у сообщений не сохранялось время, поэтому в чатах, начатых до 2.9.65, разделителей не было. Теперь для них восстанавливается время первого запроса (создание чата) и последнего сообщения, и при продолжении старого чата появляется разделитель. В начале чата — заголовок с датой. Работает в VS Code и WebStorm

## [2.9.65] — 2026-10-14

- **Список агентов — новый вид:** плотные строки без рамок, группы «Закреплено / Сегодня / Вчера / На этой неделе / Раньше», фильтр по названию, меню «⋯» (переименовать, закрепить, дублировать, в архив), навигация ↑/↓, F2, Shift+F10. Статус показывается только когда важен: «Работает», «Ошибка», синяя точка — агент закончил в фоне. В строке — незакоммиченные правки агента (+N −M) и режим «План» / «Спросить». Пустые агенты не копятся в списке, архив — внизу со счётчиком
- **Лента сообщений:** кнопка «↓» к последнему сообщению (с меткой «Новое», если ниже дописался ответ); закреплённый вопрос хода при прокрутке его ответа; мини-карта ходов у правого края и переход по ходам **Alt+↑ / Alt+↓**; подпись под ответом — модель · время · длительность; разделители по времени между ходами; длинные сообщения (вставленные логи) сворачиваются до 7 строк. Действия под ответом — у последнего ответа, у остальных по наведению
- **Пустой чат:** стартовый экран с подсказками задач, горячими клавишами и недавними агентами
- **Лента шагов:** шаги с ошибкой подсвечены, в сводке — «· N ошибок» и янтарная точка; план, оставшийся незакрытым после хода, помечен «не завершён»; «Мысли» раскрываются кликом по строке
- **Код в ответах:** без переноса по словам (горизонтальный скролл), кнопки «перенос» и «копировать» при наведении
- **Композер:** коммит и изменения — одна кнопка «Закоммитить | +N −M»; с 50 % заполнения рядом с кольцом контекста виден процент
- **Настройки:** на узкой панели вкладки — одна горизонтальная лента; первый запуск — карточка с пресетами провайдеров (OpenAI, OpenRouter, DeepSeek, Ollama, LM Studio); «MCP-серверы» и «Скиллы» переведены
- Работает в VS Code и WebStorm

## [2.9.55] — 2026-10-12

- **Jira и Confluence — меньше токенов в каждом запросе:** модели напрямую передаются только самые частые инструменты (поиск и чтение задач и страниц), остальные — через `jira_read` / `jira_write` и `confluence_read` / `confluence_write` с кратким каталогом. Инструменты занимают примерно вдвое меньше (около 3 тыс. токенов вместо 6). В режимах Plan и Ask инструменты записи по-прежнему недоступны. Отключить — `agentPanel.mcp.atlassianToolsOnDemand`

## [2.9.54] — 2026-10-12

- **Скиллы срабатывают сами:** раньше модель видела только имена скиллов и почти никогда их не загружала. Теперь в правилах сессии есть список «скилл — когда загружать», а к каждому запросу добавляется короткое напоминание. Многострочные описания в `SKILL.md` (`description: >-`) теперь читаются правильно — в том числе в Settings → Skills
- **Новые скиллы:** `executing-plans` (выполнение плана после **Собрать** — по шагам, с проверкой каждого), `bulk-text-change` (правка формулировки «везде» — сначала все вхождения и согласование охвата), `confluence-page` (чтение и запись страниц Confluence по ссылке), `work-log` (сводка за день / неделю из git и Jira, списание времени в Tempo после подтверждения)
- **Быстрее ответ в длинных чатах:** история сжимается, когда запрос доходит до 120 тыс. токенов, а не у края окна модели (у моделей с окном 1M — практически никогда). Порог — `agentPanel.autoCompact.thresholdTokens`, 0 — как раньше
- **Быстрее первый ответ после перезагрузки окна:** встроенные Jira и Confluence больше не задерживают ход на 3–15 с — проверка подключения идёт в фоне
- **Диагностика:** в Output → «Harbor Agent Timing» — размер системного промпта, число инструментов MCP и скиллов, токены запроса и попадания в кэш

## [2.9.51] — 2026-10-12

- **Скиллы:** из коробки добавлены `verification-before-completion` (не говорить «готово» без проверки в этом же ходе; если проверку запускать нельзя — честно написать, что не проверено), `systematic-debugging` (сначала первопричина, потом исправление; после трёх неудачных попыток — остановиться и обсудить подход) и `writing-plans` (план реализации в Plan-режиме в формате карточки плана с **Build**). Адаптированы из obra/superpowers (MIT). Работает в VS Code и WebStorm

## [2.9.49] — 2026-10-10

- **Композер:** вставка любых файлов из буфера — **Cmd/Ctrl+V** прикрепляет к сообщению не только картинки, но и любые скопированные файлы (PDF, код, архивы…), например после «Копировать» в Finder / Проводнике или в окне Project в WebStorm. Текстовые файлы агент получает содержимым, остальные — по имени и пути. Если скопирован файл, его иконка больше не прикрепляется лишней картинкой; скриншоты и «Копировать изображение» работают как раньше. Работает в VS Code и WebStorm
- **WebStorm:** перетаскивание любых файлов на панель — раньше принимались только картинки, теперь любые файлы (до 8 за раз, папки пропускаются), как в VS Code

## [2.9.45] — 2026-10-09

- **MCP:** правила по своим MCP-серверам в AGENTS.md — при подключении сервера Harbor записывает в AGENTS.md воркспейса отдельный блок: для чего сервер, как называются его инструменты, какие из них меняют данные (вызывать только по просьбе пользователя), инструкции самого сервера и краткий список инструментов. Для codebase-memory-mcp, context7, Playwright и GitHub — готовые подсказки (например, «на вопросы про структуру кода — граф, а не grep»). Уже настроенные серверы получат блок при первом сообщении в чат после обновления. Блок обновляется при переподключении и удаляется при удалении или отключении сервера; в нём нет локальных путей, поэтому в общем репозитории он не меняется от машины к машине. Jira и Confluence по-прежнему пишут свой раздел. Отключить — `agentPanel.mcp.agentRules.enabled`. Работает в VS Code и WebStorm

## [2.9.33] — 2026-10-06

- **Композер:** подсказки следующего сообщения — после каждого ответа агента панель предлагает вероятный следующий шаг серым текстом в пустом поле ввода; **Tab** — принять. Переключатель «Prompt suggestions» в Settings (по умолчанию вкл.). Работает в VS Code и WebStorm
- **MCP:** новый пресет «Jira» (Server / Data Center через mcp-atlassian) — токен хранится в защищённом хранилище и не попадает в файлы проекта; после проверки подключения в AGENTS.md добавляется раздел с инструкцией и готовые MCP-конфиги без токена для других агентских инструментов. Подсказка при TLS-ошибках с корпоративным сертификатом
- **Скиллы:** из коробки добавлены `code-review`, `debug-from-logs`, `dependency-upgrade`, `figma-to-code`, `frontend-review`, `jira-task`, `pr-description`, `safe-refactor`, `verify-endpoint`, `write-tests`. Встроенные скиллы теперь обновляются автоматически до новой версии, пока вы их не меняли
- **Мысли модели:** карточки рассуждений теперь на языке интерфейса, включая русский
- **Исправления:** стабильнее генерируются названия чатов и подсказки — модели с постоянным reasoning больше не возвращают пустой результат

## [2.9.29] — 2026-10-06

- **Композер:** проверка безопасности перед отправкой (и постановкой в очередь) — над полем ввода появляется плашка, если в тексте найдены:
  - секреты (ключи OpenAI/Anthropic, GitHub/GitLab/Slack/Stripe/Google/AWS, JWT, приватные PEM-ключи, пароль в URL, `password=` / `token:`) — кнопка «Замаскировать секреты» заменяет значение на `<redacted>`;
  - prompt injection («ignore previous instructions», `<system>`, `<|im_start|>`) и скрытые Unicode-символы (zero-width / bidi / tag) — кнопка «Убрать скрытые символы»;
  - разрушительные команды (`rm -rf`, `git push --force`, `git reset --hard`, `curl | sh`, `DROP TABLE` и др.) — только предупреждение.
  
  «Отправить как есть» разрешает отправку только этого текста; работает в VS Code и WebStorm (общий webview)

## [2.9.27] — 2026-10-06
